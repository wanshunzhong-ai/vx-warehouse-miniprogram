0先看懂全局：这套东西由哪三部分组成

花 3 分钟看完这一节，后面每一步你都会知道自己在干什么。

①

手机端小程序

仓库管理员、主管、员工用的。扫码出入库、查库存、看流水、管人员。跑在微信里。

②

后端数据库（云服务）

所有物品、库存、流水、账号都存这里。手机端只是「显示屏」，真正的账本在云端。

③

电脑端打码工具

一个网页文件，不联网也能用。粘贴物品清单 → 批量生成二维码标签 → 打印出来贴到物品上。

你日常的作业动线是这样的：

采购到货→ 电脑端打码并打印→ 贴到每件物品上→ 手机扫码入库→ 以后扫码出入库→ 流水自动留痕
如果你只想「先看看长什么样」

直接跳到 第 3 章。跳过后端配置也能编译出完整界面，登录页、三个后台、扫码页全都看得见 —— 只是登录时会提示连不上数据库。看爽了再回来做第 4、5 章。

2把代码拿到自己电脑上

选一种就行，推荐「方式一」。

方式一：下载 ZIP（小白首选）

1打开代码仓库页面

浏览器访问：

https://github.com/wanshunzhong-ai/vx-warehouse-miniprogram
2下载并解压

点右侧绿色的 Code 按钮 → Download ZIP。

下载完得到一个 vx-warehouse-miniprogram-main.zip，右键「全部解压缩」。

方式二：用 Git 克隆（会 Git 的话更快）

1打开终端执行一行命令

Windows 在文件夹地址栏输入 cmd 回车即可打开命令行；macOS 打开「终端」。

国内网络如果卡住不动，加一个代理参数（把 7890 换成你自己的代理端口）：

确认下载完整

  ├── app.js  app.json  app.wxss

  └── miniprogram_npm/   ← 云 SDK 构建产物，缺了会连不上后端

没有看到 miniprogram_npm？

那是「隐藏文件夹」被折叠了，不碍事。真的缺了也不要紧 —— 第 3 章第 3 步的「构建 npm」会把它重新生成出来。

3导入微信开发者工具并跑起来

做完这一章，你就能在电脑上看到完整的小程序界面了。

1新建项目

打开微信开发者工具 → 扫码登录 → 左侧选「小程序」→ 点「+」新建。

在新建面板里填四项：

  • 目录：点右边文件夹图标，选中仓库根目录 —— 就是能直接看到 project.config.json 和 miniprogram 文件夹的那一层（不是里面的 miniprogram）。
  • AppID：填你在第 1 章拿到的 AppID。下面「测试号」不建议选，测试号无法发布。
  • 项目名称：随便填，比如 仓库物品管理。
  • 后端服务：选「不使用云服务」（我们用的是自己的工作台云服务，不是微信云开发）。

点「确定」。

它提示「当前目录不是小程序项目目录」？

说明你选错层级了，往上或往下退一层。正确的那一层里直接就能看到 project.config.json 这个文件，代码在它旁边的 miniprogram 文件夹里。

2改 AppID（如果第 1 步懒得起用了默认值）

如果导入后发现提示项目不属于你，就改这里：左侧文件树打开 project.config.json，把 "appid" 那一行的值换成你自己的 AppID，保存（Ctrl/Cmd + S），然后在工具里点「编译」。

{
  // 换成你自己的小程序 AppID
  "appid": "wx你的AppID",
  "projectname": "vx-warehouse",
  ...
}
3构建 npm（关键一步，别跳过）

顶部菜单栏：工具 → 构建 npm。

等右下角弹出「构建成功」的小提示。

这一步在干什么？

把 node_modules 里的云服务 SDK 编译成小程序能用的形式，输出到 miniprogram/miniprogram_npm（这个关系已经写在 project.config.json 的 packNpmRelationList 里，不用手动配）。仓库里已经预置了一份构建产物，所以正常情况下不构建也能跑；但如果你之后升级了 SDK（改了 package.json），就必须重新构建。

报「找不到 node_modules」？

说明你还没装 Node.js。回到第 1 章第 4 项装好 Node.js，然后在项目文件夹里执行 npm install（在地址栏输 cmd 打开命令行后运行），再回来点「构建 npm」。

4编译

点工具栏上的「编译」按钮（或按 Ctrl/Cmd + B）。

5验收：你应该看到什么

左侧模拟器里会显示登录页：一个「仓库物品管理」的标题，加上账号、密码两个输入框和登录按钮。

看到登录页 = 第 3 章成功

不管有没有配后端，界面都能正常显示 —— 界面是本地代码画的，不依赖数据库。
注意：小程序每次打开都会回到这个登录页，这是刻意设计的（多人共用设备不串号），不是 bug。

没看到登录页，而是白屏或报错？

先去第 8 章「报错排查手册」按症状对号入座。最常见的两种情况：漏了「构建 npm」，或者用的是别人的 AppID。

4连接后端数据库（三种方案，挑一个）

只有配好了后端，才能真正登录、看到库存数据。

方案适合谁难度数据归属
A 直接用现成的 只想赶紧跑起来看看效果、试用一下 最简单 跟原项目共用一份
B 自己开一套 要正式用、数据要自己掌控 （推荐） 中等 完全独立
C 自建 PostgreSQL 只做技术评估、或要把后端搬到自己服务器 进阶 自己的服务器

方案 A：直接用现成的云服务（最快）

1什么都不用做

代码里已经内置了这套云服务的连接信息，在 miniprogram/utils/cloud.js：

const publicConfig = {
  endpoint: 'https://mp-api.app.workbuddy.host',
  publishableKey: 'wbpk_V5TDHdOmlEdRT5Esp5xvPo_...'
}

直接跳到第 5 章，用管理员账号登录即可。

别拿它正式用

这是别人的环境，里面是演示数据，你改动它会影响到别人；而且你随时可能失去访问权。正式使用请走方案 B。

方案 B：自己开一套云服务（推荐）

1让 WorkBuddy 开通云服务

在 WorkBuddy 对话里直接说：

给这个微信小程序项目开通云服务（云数据库 + 文件存储），
然后把 endpoint 和 publishableKey 给我。

WorkBuddy 会创建一套属于你的云环境，并返回两个值：

  • endpoint：形如 https://mp-api.app.workbuddy.host（这是平台的统一网关，一般不变）
  • publishableKey：形如 wbpk_XXXXXXXX_YYYYYYYY（你这个应用专属）

同时它会给你一个 applicationId（形如 wbapp_XXXXXXXX）。

2把连接信息填进代码

打开 miniprogram/utils/cloud.js，把 publicConfig 里的两个值换成你自己那套，保存：

const publicConfig = {
  endpoint: '你的 endpoint',
  publishableKey: '你的 publishableKey',
}
全项目只有这一处需要改

所有页面都通过 miniprogram/utils/cloud.js 的 getCloud() 访问后端，换环境只改这一个文件，别去页面里改。

3把数据库结构建起来

仓库的 sql/ 文件夹里有四个脚本，必须严格按编号顺序执行：

脚本作用能不能跳过
01-schema.sql建 4 张表（物品 / 账号 / 会话 / 流水）、索引、行级安全策略与表权限不能
02-functions.sql建约 30 个服务端函数 —— 全部业务逻辑和权限判断都在这里不能
03-bootstrap-admin.sql种下第一个管理员账号（员工不能自己注册，所以第一个管理员只能手工建）不能
04-demo-data.sql灌少量演示数据，让界面一打开就有东西看可跳过

怎么执行？把这句话发给 WorkBuddy 就行：

请把项目里的 sql/01-schema.sql、sql/02-functions.sql、
sql/03-bootstrap-admin.sql、sql/04-demo-data.sql 依次执行到
我刚开通的云服务数据库里。执行 03 时把初始密码设成 <你自己的密码>。
执行 03 之前必须先改密码！

脚本里 c_password 默认是占位值 ChangeMe@2026。脚本有守卫，不改就直接执行会报错退出 —— 这是故意的，防止你把一个全网都知道的密码用成正式密码。
自己手动执行的话：打开 sql/03-bootstrap-admin.sql，把第 20 行改成你的密码，再整段跑。

4验收：确认建好了

让 WorkBuddy 跑这条查询，或自己在数据库控制台执行：

SELECT id, username, name, role, status, must_change_password
FROM public.staff ORDER BY id;

应该看到恰好一行 admin / admin / 系统管理员 / active。
（如果你也执行了 04-demo-data.sql，这里就只有这 1 个账号 —— 演示账号表是另外一份文档，不在 SQL 里。）

再看一眼表有没有建全：

SELECT table_name FROM information_schema.tables
WHERE table_schema='public' ORDER BY table_name;

应包含 items、staff、staff_sessions、stock_records。

方案 C：自建 PostgreSQL（进阶）

先说清楚：这条路不是「改个地址」就完事

手机端用的是云服务 SDK（miniprogram_npm/@tencent-ai/workbuddy-cloud-sdk）来访问数据库的，它的寻址方式是「endpoint + publishableKey」，没法直接指向一台任意的 PostgreSQL。

所以自建库有两种走法：

  • 只做评估 / 迁移数据：sql/01 和 sql/02 是标准 PostgreSQL 14+ 脚本，可以直接在任何 PG 实例（Supabase、阿里云 RDS、本机 Docker）上跑通。用它来验证数据模型、迁移历史数据都行。
  • 真的要换后端：需要另写一层数据访问，把 miniprogram/utils/api.js 里对 getDB() 的调用替换成你自己的 HTTP 接口（比如 Supabase 的 REST 或自建 API）。工作量不小，建议先完成方案 B 跑通业务，再考虑迁移。

如果只是想在本机验证 SQL：

# 用 Docker 起一个临时 PostgreSQL（需要本机有 Docker）
docker run --name vx-pg -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgres:16

# 按顺序灌脚本
psql "postgresql://postgres:postgres@localhost:5432/postgres" -f sql/01-schema.sql
psql "postgresql://postgres:postgres@localhost:5432/postgres" -f sql/02-functions.sql
psql "postgresql://postgres:postgres@localhost:5432/postgres" -f sql/03-bootstrap-admin.sql
psql "postgresql://postgres:postgres@localhost:5432/postgres" -f sql/04-demo-data.sql
脚本里那三个 auth.* 函数是什么？

01 脚本开头会尝试创建 auth.uid() 等三个辅助函数，云平台通常已经内置了；如果你的库已存在，脚本会跳过，这不影响使用。

5创建第一个管理员并登录

到这里，你已经能把整套系统转起来了。

1用管理员登录

在开发者工具里点「编译」，在模拟器的登录页输入：

  • 账号：admin
  • 密码：你在 sql/03-bootstrap-admin.sql 里设的那个

登录后进入「管理中心」，底部是 4 个页签（工作台 / 物品 / 记录 / 我的），没有扫码入口 —— 这是设计如此，管理员专职管人和看全局，不参与出入库。

首次登录会强制你改一次密码，改完即可正常使用。

2把人员建起来

接下来的顺序建议这样（都在小程序里点几下就行）：

  1. 加主管：「我的」→ 人员管理 → 添加账号 → 身份选「主管」。管理员添加的账号立即生效，可以直接登录。
  2. 加员工：由主管去加。主管添加的账号状态是待审批，此时员工登录会被拦下。
  3. 审批：管理员到「人员管理」里点通过（可以顺手「通过并设为主管」），账号才变成可用状态。
为什么员工不能自己注册？

内部仓库系统，不该让任何人凭手机号就能进来。所以刻意设计成「主管提交 → 管理员批准」，第一条防线在流程上。

管理员主管员工
后台名称管理中心主管台工作台
底部页签4 项（无扫码）5 项5 项，扫码是中间凸起的大按钮
扫码出入库❌✅✅
建档 / 改档 / 停用 / 批量导入✅✅❌
扫到新码现场建档入库❌✅✅

管理员工全部人仅自己提交的❌
改身份 / 删账号✅❌❌
导出记录✅✅❌

页面上看到的按钮、能进的页面，全部由 miniprogram/utils/roles.js 一份配置驱动 —— 想调权限只改这一个文件，不用去每个页面改。

6电脑端打码工具（打印二维码标签）

纯网页，双击就能用，不需要安装、不需要联网。

1打开工具

在解压出来的文件夹里，双击 pc-tools/index.html，会用默认浏览器打开。

不要单独把这个文件拷到别处！

它依赖 ../miniprogram/utils/qr.js（二维码编码器）。拷走单独打开会变成一张空白页。要发给别人，把整个文件夹打包发。

2粘贴清单

从 Excel 里选中你的物品清单（包含 分类、名称、规格、单位、库位、数量 等列），Ctrl + C 复制，然后粘贴到网页左上角的输入框里。

3选择「是否逐件展开」

这一步决定了你的管理模式，两种都常用：

做法效果适合什么
点「按数量逐件展开」 数量 5 的一行，会拆成 5 个独立编号（A-0001-1 ~ A-0001-5），每件一张码、各自 1 件库存 扳手、电动工具、设备 —— 要追踪到具体某一件的
不展开 一行一个编号，按数量记库存（B-0001 共 40 卷） 螺丝、垫片、胶带 —— 散装、按量领用的
4打印

页面会实时生成带二维码的标签。点「打印」，在打印对话框里选标签打印机，调节缩放让二维码大小合适。

没有标签打印机也行：普通 A4 打印后裁剪，一样能用。

5贴码 → 手机扫码入库

二维码贴在物品上之后，用手机小程序去扫：

  • 已建档的编号 → 直接进入入库流程，填数量即可。
  • 没建档的编号 → 手机会提示「这是新物品」，让你现场填名称、规格、库位，保存后建档和入库一步完成。
  • 逐件赋码时更省事：同型号的第 2 件起会自动带出第 1 件填过的信息，点一下就能过。

所以有两条路可选，选哪条都行：① 打码贴上去直接扫（省掉建档步骤）；② 先把清单导入小程序建档，再扫码（「我的 → 批量导入」粘贴一次）。

7手机真机预览与正式发布

模拟器只能看，扫码必须用真机。

7.1 真机预览（开发阶段）

1点「预览」

开发者工具工具栏点「预览」，会生成一个二维码。用手机微信扫这个码，就能在手机上打开你的小程序。

预览版无需审核、随时可看，改了代码重新编译再扫一次即可。

2测试扫码

在真机上：
· 员工账号登录后，底部导航中间的凸起圆形大按钮就是扫码入口；
· 顶部的「扫码入库 / 扫码出库」两张方向大卡，点哪个进去就是哪个方向，进去后方向会被锁定（页面上会显示彩色方向条）。

第一次扫码没反应？

手机可能拒绝了相机权限。到微信「我 → 设置 → 隐私 → 授权管理」里把相机权限打开，重新扫码。

真机上要把「不校验合法域名」关掉吗？

不用。项目 project.config.json 里已经关掉了域名校验，预览阶段能正常访问云服务。上正式版前如果遇到网络问题，再去「开发管理 → 服务器域名」里核对。

7.2 正式发布（给全公司用）

1上传代码

开发者工具点「上传」，填一个版本号（如 1.0.0）和备注，确定。

2在微信后台提交审核

登录 mp.weixin.qq.com → 左侧「版本管理」→ 找到刚上传的版本 → 「提交审核」。

审核一般 1–3 个工作日。审核时注意：微信会要求你提供一个可登录的测试账号（他们会被登录页挡住），所以提前在「审核备注」里把测试账号密码写清楚 —— 别忘了先建好一个演示用的员工账号。

3发布

审核通过后点「发布」。之后全公司的人都能通过微信搜索到它，或者你把小程序码发到群里让大家扫码进入。

发布前必做的三件事

① 改掉演示密码：管理员账号必须换成强密码，人员管理里把不需要的账号停用或删除。
② 清掉演示数据：物品、流水如果不需要，在界面上删除或停用。
③ 确认后端不是你借来的：miniprogram/utils/cloud.js 里必须是你自己的 publishableKey（方案 B），别把别人的环境发布给全公司用。

现象 / 报错原因怎么解决
模拟器一片空白，控制台红字提示找不到模块 没执行「构建 npm」，miniprogram_npm 缺失 顶部菜单 工具 → 构建 npm。如果报「找不到 node_modules」，先装 Node.js，并在仓库根目录（有 package.json 的那一层）执行 npm install。

登录时提示网络错误 / 连接失败 后端没配、或 publishableKey 填错 检查 miniprogram/utils/cloud.js 里的 endpoint 和 publishableKey；确认第 4 章的 SQL 已经执行过。
登录提示「账号或密码错误」 账号不存在，或密码不是你在 03 脚本里设的那个 执行 SELECT username,role,status FROM public.staff; 看账号在不在、状态是不是 active。
登录提示账号待审批 / 已驳回 / 已停用 账号状态不对，这是正常拦截 管理员在「人员管理」里审批通过或重新启用。注意：主管不能审批，只有管理员可以。
主管想启用一个「已驳回」的账号，提示无权操作 设计如此：主管只能在「正常 / 已停用」之间切换 让管理员处理。否则主管把「已驳回」改回启用，等于绕过了审批。
管理员在详情页看不到出入库按钮 设计如此：管理员不参与出入库 用主管或员工账号操作。若确实要管理员扫码，去 miniprogram/utils/roles.js 给 admin 加上 stock.change 能力。
员工登录后底部没有「扫码」这项 员工的扫码被做成了中间凸起的圆形大按钮 它就在页签正中间，圆形的那个。不是普通页签样式，别找错了。
点「扫码」没反应 / 提示无法使用相机 手机没给相机权限 微信「我 → 设置 → 隐私 → 授权管理」里打开相机权限，重启小程序。
扫码后提示「物品已停用」 该物品被停用了，stock_change 会拒绝对停用物品出入库 到物品页顶部切到「已停用」筛选，找到它后恢复使用（需要主管及以上）。
扫码提示「编号已被占用」 这个编号已经有档案了 本意是防止重复建档。到物品页搜一下这个编号，直接走正常出入库即可。
逐件赋码后，5 件只打印出 4 张码 （已在代码中修复）编号冲突时会吃掉一件 确认用的是仓库最新代码，重新打开 pc-tools/index.html（浏览器可能有缓存，用 Ctrl + F5 强制刷新）。
散装物品被领走后，列表里冒出一堆「库存预警」 （已在代码中修复）安全库存为 0 的物品不该参与预警 确认代码是最新的。判定口径是 状态正常 且 安全库存 > 0 且 库存 ≤ 安全库存，安全库存填 0 表示「不预警」。
提示「请填写姓名」但我在填的是物品名称 （已在代码中修复）两个错误码文案串了 更新到最新代码。miniprogram/utils/util.js 的错误映射里 ITEM_NAME_REQUIRED 必须排在 NAME_REQUIRED 前面。
点了登录按钮，看起来是灰的却能点进去 （已在代码中修复） 更新代码。最新版是按钮真的 disabled，不是只改透明度。
每次重新编译都要重新登录 这就是设计，不是 bug 登录态只存在内存里、不落盘，所以冷启动必回登录页。多人共用设备不串号；只是切后台再切回（进程没被回收）仍保持登录。
上传代码时提示包体积过大 把不该打包的目录打进去了 检查 project.config.json 的 packOptions.ignore 里是否还有 node_modules、sql、pc-tools、.md、.html —— 这几项必须保留。
双击 pc-tools/index.html 是空白页 文件被单独拷走了，找不到 ../miniprogram/utils/qr.js 放回项目里的原位置打开，或把整个文件夹一起拷贝。
SQL 执行 02 时提示函数已存在 重复执行了，脚本用的是 CREATE OR REPLACE 正常现象，可以忽略。但如果提示「Could not choose the best candidate function」，说明库里存在同名的旧重载，需要先删掉旧函数再执行。

B附录：安全与维护须知

上线前必做

  • 管理员密码改成强密码（12 位以上，含大小写数字符号）
  • 人员管理里清掉不需要的演示账号，或全部停用
  • miniprogram/utils/cloud.js 里是自己的 publishableKey，不是借来的环境
  • 确认演示数据（物品、流水）已清理干净
  • 给仓库主管做一次 15 分钟的培训：怎么扫码、怎么审批、怎么找回停用物品

数据安全：三层防线

防线位置防什么
第一层：登录 账号密码 + 30 天令牌，密码用 bcrypt 存储 没账号的人进不来
第二层：角色 miniprogram/utils/roles.js 控制界面上显示什么 普通用户看不到不该看的按钮
第三层：服务端 数据库函数每次都校验令牌和角色（SECURITY DEFINER） 反编译客户端直接调接口，也拿不到越权数据
为什么第三层最重要？

小程序能被反编译，接口能被直接调用。所以这套系统把「谁有权做什么」全部写在数据库函数里，客户端只负责显示。哪怕有人把代码全扒开，也改不了自己不是管理员的这个事实。
因此：不要为了「方便」给 staff / stock_records 表补表级权限，那等于把这道门拆掉。

日常维护

什么时候做什么
人员变动人员管理里停用（不要直接删，保留历史流水的操作人记录）；新员工走「主管提交 → 管理员审批」
物品停用用「停用」而不是删除。停用后仍可在物品页切到「已停用」找回；删除会丢历史关联
库存对不上在「记录」里按物品筛流水，每条都有前库存 → 后库存，能一路倒推到底哪一步错了
要出报表管理员或主管在「记录」页用「导出」，拿到表格做二次加工
升级了云 SDK重跑 npm install → 开发者工具「构建 npm」→ 重新编译
保管好你的 AppID 和账号密码

本指南所配套的代码仓库是公开仓库，所以里面不含任何真实密码。你自己的密码请单独保管，也不要把带真实密码的账号表提交进仓库。
