# 仓库物品管理小程序 · 技术栈与功能介绍

> 微信小程序 + 云端 PostgreSQL + 电脑端离线打码工具
> 覆盖「采购到货 → 分类清点 → 打码贴码 → 扫码入库 → 领用出库 → 流水追溯」的完整闭环。

---

## 一、技术栈介绍

### 1. 客户端：微信小程序原生开发

没有使用 uni-app、Taro 等跨端框架，直接采用微信小程序原生技术栈：

| 层 | 技术 | 说明 |
|---|---|---|
| 结构 | WXML | 原生模板语法，`wx:if` / `wx:for` 驱动条件与列表渲染 |
| 样式 | WXSS + rpx | 750rpx 设计稿宽度自适应，一套样式适配大小屏 |
| 逻辑 | JavaScript (ES6) | 13 个页面，按角色动态装配底部导航 |
| 组件 | 自定义 tabBar | `custom: true`，三种身份三套导航，员工端中间凸起圆形扫码键 |

选择原生而非框架，换来的是**零构建、零运行时开销、包体最小**——整个小程序没有任何图片资源，
所有图标（物品、扫码、记录、人员等）全部用纯 CSS 绘制，因此代码包非常轻。

### 2. 服务端：CloudBase 云托管 PostgreSQL

后端没有自建服务器，而是使用**托管式 PostgreSQL 数据库 + 服务端函数**：

- **数据库**：4 张核心表 —— 物品主档 `items`、人员 `staff`、会话 `staff_sessions`、库存流水 `stock_records`
- **接口层**：30 个 PostgreSQL 函数（`SECURITY DEFINER`）承担全部业务逻辑，客户端通过 SDK 以 RPC 方式调用，
  **没有 REST 接口暴露、没有裸表读取**
- **对象存储**：物品位置照片放在云端对象存储，物品档案里只留一条对象路径，
  访问时现换短期签名链接（图片本体不进数据库，列表查询不会被大字段拖慢）
- **会话机制**：登录签发令牌写入 `staff_sessions`，有效期 30 天，所有业务函数入参第一个就是 `p_token`，
  由 `staff_require(token, min_role)` 统一校验身份与角色等级

### 3. 安全设计：三道防线

1. **权限收紧**：`stock_records` / `staff` / `staff_sessions` 三张表**零表级授权**，
   匿名与普通身份拿不到任何一行数据，只能经由带令牌的函数访问；
   物品表仅开放 `SELECT`（扫码查档需要），写入一律走函数。
2. **服务端兜底**：角色校验写在数据库函数里，绕过界面直接调接口同样会被拒绝，
   越权请求拿不到数据。
3. **并发安全**：库存变更统一走 `stock_change(p_token, ...)`，函数内部使用
   `SELECT ... FOR UPDATE` 行级锁 + 写流水，保证多人同时扫码不会算错库存，也不会出现负库存。

### 4. 自研二维码编码器

项目内置了零依赖的二维码编码器 `utils/qr.js`：

- 完整实现 QR Code 的 Reed-Solomon 纠错编码、掩码评估、格式信息生成
- 支持版本 1–6，字节模式，最大 106 字节——物品编号（如 `A-0001-3`）绰绰有余
- 同时导出 `toSvg()` 给电脑端工具用，手机端和电脑端共用同一套编码逻辑，生成的码完全一致

因为是自研，所以不依赖任何第三方二维码库，也不受网络与 CDN 影响，**离线可用**。

### 5. 电脑端工具：单文件纯前端

`pc-tools/index.html` 是一个可双击打开的单文件网页，零依赖、零安装、完全离线：

- 粘贴 Excel 清单 → 按数量**逐件展开**为独立编号 → 生成二维码标签 → 直接调用浏览器打印
- 也可导出 CSV 或复制表格，供小程序端「批量导入」粘贴

### 6. 工程化：三套自检脚本

改完代码必须跑三个 Node 脚本：结构语法与事件函数校验、模块依赖图全量加载校验、
角色权限矩阵与导航联动校验。**权限分工、登录策略、缓存传参键**这些容易在改动中被破坏的约定，
都有断言盯着，防止"改 A 坏 B"。

## 二、功能介绍

### 1. 三级身份与权限分工

账号密码登录，按角色进入不同后台，三种身份职责刻意区分：

| 能力 | 管理员 | 主管 | 员工 |
|---|:---:|:---:|:---:|
| 物品建档 / 编辑 / 停用 / 批量导入 | ✅ | ✅ | — |
| 扫码出入库 | — | ✅ | ✅ |
| 扫码即建档 | — | ✅ | ✅ |
| 上传物品位置照片 | ✅ | ✅ | ✅ |
| 添加账号 | 直接生效 | 提交待审批 | — |
| 审批账号 | ✅ | — | — |
| 管理员工 | 全部人员 | 仅自己提交的 | — |
| 修改身份 / 删除账号 | ✅ | — | — |
| 流水导出 | ✅ | ✅ | — |

管理员**不参与出入库**，专职管人与全局监控；主管可以带人干活但只管得着自己招募的员工；
员工只做一线扫码，改不了档案也停用不了物品。这套分工在界面、客户端能力表、数据库函数三层同时生效。

### 2. 物品档案管理

- 按分类自动生成编号（五金 A-、电气 B-、劳保 C-、办公 D-、工量具 E-、包装 F-）
- 记录名称、规格、单位、货架位、安全库存
- **二维码内容就是物品编号**，扫码即达档案
- 物品「停用」是一等状态而非删除：停用后禁止出入库但历史流水完整保留，可随时恢复
- 支持按关键字搜索、按分类筛选、在用/已停用分段查看

### 3. 物品位置照片

档案里的「库位」是一行字，说了等于没说——「B 区货架」到底是哪一格？所以给每件物品配一张**现场实拍图**：

- 详情页拍一张（或从相册选一张），对着货架拍，照片本身就是位置说明
- 点开可看大图、可放大，对比货架细节；可以随时更换或删除
- 图片存**云端对象存储**，物品档案里只记一条对象路径 —— 列表查询不会被几十 KB 的图片拖慢；
  访问时客户端现换一个短期签名链接（最长 1 小时，只在内存缓存、临期自动续）
- 物品列表给有照片的物品打一个「位置图」角标，但不加载图片：
  一次二三十条列表各拉一张图太慢，也不必要，图片留到详情页再看
- 三种身份都能拍（谁在现场谁拍）：照片记录的是现场事实，动不了库存、也不影响账目。
  写入仍然只走带令牌的服务端函数，且路径必须落在团队共享前缀内

### 4. 扫码出入库

- 扫码页顶部是**「扫码入库」/「扫码出库」两个方向大卡**，选定方向后直达扫码，
  方向一路带到数量录入页并**锁定**（顶部显示彩色方向条，可一键「换个方向」）
- 扫码 → 带出物品档案 → 填写数量 → 提交，成功页显示**变动前后库存对比**
- 员工端底部导航正中间是**凸起的圆形大按钮**，一步直达扫码

### 5. 扫码即建档（采购到货的完整链路）

这是本系统最有特色的一条链路：

1. 电脑端粘贴采购清单，**按数量逐件展开**成独立编号（5 件 → `A-0001-1` … `A-0001-5`，一物一码）
2. 打印标签，剪开贴到每件实物上
3. 手机扫码——若该编号尚未建档，系统按**前缀找同族档案**（`A-0001-3` → 找 `A-0001-*`），
   有则一键套用名称规格，没有则现场填写，**建档与入库原子完成**，不会出现"建了档却没进账"

### 6. 库存预警

首页大字卡实时显示低库存条目数，点击直接下钻到对应的物品列表。
判定口径为「在用 + 设置了安全库存 + 实际库存 ≤ 安全库存」，服务端与客户端三处口径完全一致。

### 7. 流水追溯

每一笔库存变动都留痕：谁、什么时候、对哪件物品、入还是出、数量多少、变动前后库存。
支持按操作人、按物品、按时间筛选，并可按权限导出。

### 8. 人员账号管理

- 主管添加员工 → 进入**待审批**；管理员审批通过后才可登录
- 审批「通过 · 设为主管」这类**提权操作必须二次确认**，防止误点
- 支持重置密码（系统随机生成）、停用/启用、修改身份、删除账号
- 账号列表按「待审批 / 正常 / 已停用 / 已驳回」分段查看

### 9. 个人中心

查看个人信息、修改姓名与密码、查看自己的历史操作流水。

### 10. 登录策略

采用「**每次打开小程序都要重新登录**」的策略：登录令牌只保存在内存中，绝不写入本地存储，
冷启动必定回到登录页。这样即使手机被他人短暂拿到，也无法直接进入系统。
（切到后台再切回、进程未被回收时保持登录，避免扫码等系统弹窗把操作到一半的人踢下线。）

---

## 三、一句话总结

**端上零框架、零图片、零第三方依赖，云上无裸接口、写操作全带令牌与行锁** ——
一个为内部仓库场景量身打造的轻量、安全、离线可用的物品管理系统。
