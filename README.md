# 仓库物品管理小程序

内部仓库的物品建档、二维码标签、手机扫码进出库与流水追溯。

微信小程序（原生）+ 云服务后端 + 电脑端离线标签工具，三部分。

## 功能

- **物品档案**：编号、名称、规格、分类、单位、库位、安全库存，支持停用/恢复/删除
- **独立二维码**：每个物品一个二维码，内容就是物品编号（纯 ASCII，扫码枪 / PDA 也能读）
- **扫码出入库**：扫码或手输编号 → 选入库/出库 → 填数量，库存与流水自动更新（服务端行锁保证并发安全）
- **流水追溯**：谁、什么时候、对哪个物品、做了多少，前库存 → 后库存链条完整可查
- **库存预警**：低于安全库存的物品自动挑出来
- **人员与审批**：员工账号由主管添加、管理员审批后才可登录
- **电脑端工具**：粘贴 Excel → 自动生成编号与二维码标签 → 打印贴码 → 导出 CSV，
  支持「按数量逐件展开」（5 件 → 5 张独立编号的码）

## 作业流程：采购到货 → 分类 → 打码 → 贴码 → 扫码入库

| 步骤 | 做什么 | 在哪做 |
|---|---|---|
| ① 打码 | 粘贴清单 → 点「按数量逐件展开」→ 打印标签 | 电脑 `pc-tools/index.html` |
| ② 贴码 | 把二维码贴到每一件物品上 | 现场 |
| ③ 入库 | 扫码：已建档的直接入库；未建档的现场填名称，**建档 + 入库一步完成** | 手机小程序 |

**逐件赋码**：「按数量逐件展开」把「库存 5」的一行拆成 5 个独立编号（`A-0001-1` ~ `A-0001-5`），
每件一张码、各自 1 件库存，可以定位到具体某一件。适合扳手、电动工具、设备这类要逐件追踪的物品；
螺丝、垫片这类散装件不展开，一行一个编号、按数量记库存即可。

**扫码即建档**：贴完码直接扫，物品若还没档案，手机会让你现场填一次名称 / 规格 / 位置，
保存后建档与入库一起落库。逐件赋码时更省事——同型号第 2 件起会自动带出第 1 件填过的信息，
点一下就能过，不用把名称规格重复填 N 遍。

因此有两条路可选：

- **逐件码 + 扫码即建档**：打完码贴上去就能用，跳过批量导入。
- **先建档再扫码**（原有方式）：导出清单 → 小程序「我的 → 批量导入」一次建好档案。

## 三种身份

登录后按账号的身份直接进入不同的后台。

**每次打开小程序都要重新登录**：登录态只保存在内存里，**不写入本地缓存**，也不做自动登录。
冷启动（首次打开、被微信回收后重开、开发者工具点「编译」）一律回到登录页，必须输入账号密码。
这样多人共用一台设备不会串号，演示三种身份时也能随时换人。
（小程序仅切到后台、进程仍活着时保持登录，否则扫码、选文件等系统弹窗会把操作到一半的人踢下线。）

| | 管理员 | 主管 | 员工 |
|---|---|---|---|
| 后台名称 | 管理中心 | 主管台 | 工作台 |
| 底部导航 | 4 项（无扫码） | 5 项 | 5 项（**扫码是中间凸起的大按钮**） |
| 建档 / 改档 / 导入 | ✅ | ✅ | ❌ |
| 扫码出入库 | ✅ | ✅ | ✅ |
| 添加账号 | ✅ 直接生效 | ✅ 提交待审批 | ❌ |
| 审批账号 | ✅ | ❌ | ❌ |
| 删除物品 / 导出记录 | ✅ / ✅ | ❌ / ✅ | ❌ |

底部导航、标题、主题色、首页内容、按钮可见性全部由 `utils/roles.js` 一份配置驱动。

「扫码即建档」（`item.quickcreate`）是出入库链路的延伸，所以员工也有；它**不等于**「建档」——
员工仍然进不了新建物品页，也删不了档、停不了用。

**员工不能自己注册**：主管添加 → 状态 `pending`，此时登录会被拦（`ACCOUNT_PENDING`）；
管理员审批通过 → `active`，才能登录，且首次登录会被要求修改初始密码。

## 本地运行

1. 用微信开发者工具打开本目录（小程序根目录就是仓库根目录）。
2. 安装依赖并构建 npm：
   ```bash
   npm install
   ```
   然后在开发者工具里执行「工具 → 构建 npm」，生成 `miniprogram_npm/`（仓库里已包含一份构建产物，
   升级 SDK 后需要重新构建）。
3. 编译预览。首次登录会提示修改初始密码（仅针对审批通过的新账号）。

云环境配置集中在 `utils/cloud.js` 的 `publicConfig`（endpoint + publishableKey），换环境只改这里。

## 后端

数据落在 WorkBuddy 云服务（PostgreSQL）。关键设计：

- 数据是**团队共享**的，不是按人隔离；`items` 对客户端只开放只读（扫码查物品需要）。
- `stock_records` / `staff` / `staff_sessions` **零表级授权**，所有写入必须经过带令牌的
  `SECURITY DEFINER` 函数 —— 绕过界面直接调接口也拿不到越权数据。
- 库存只能通过 `stock_change(p_token, ...)` 修改（内部 `SELECT ... FOR UPDATE` 行锁 + 写流水），
  客户端不允许直接 update `items.qty`。
- 扫到未建档的编号时走 `staff_scan_create_in(p_token, ...)`：建档与入库在一次调用里原子完成，
  不会出现「建了档却没进账」；管理员与 `stock_change` 一样被排除在外。
- `staff_code_family(p_token, code)` 按编号前缀找同族已有档案（`A-0001-3` → `A-0001-*`），
  用于逐件赋码时自动带出信息。
- 密码用 `pgcrypto` 的 bcrypt 存储；登录成功后下发 30 天有效的令牌
  （客户端只在**本次运行的内存**里保留，不落盘，所以每次冷启动都要重新登录）。
- 登录失败时也会跑一次 hash 比较（诱饵），避免按响应时间枚举账号。

## 电脑端工具

直接双击打开 `pc-tools/index.html` 即可（纯前端离线，不依赖后端）。
注意它依赖 `../utils/qr.js`，**不能单独把这个文件拷走**。

流程：粘贴 Excel → 生成编号 + 二维码标签 → 打印贴码 → 扫码入库。

两种用法：

- **逐件追踪**（工具、设备）：先在清单里填好每类的件数，点「按数量逐件展开」再打印。
  每件一个独立编号、一张码，贴上去之后扫码即可入库，不必先去小程序导入。
- **整体建档**（散装件）：不展开，一行一个编号按数量记库存；把清单复制 / 导出到小程序
  「我的 → 批量导入」粘贴一次建好档案，之后扫码出入库。
