# 仓库物品管理小程序

内部仓库的物品建档、二维码标签、手机扫码进出库与流水追溯。

微信小程序（原生）+ 云服务后端 + 电脑端离线标签工具，三部分。

## 功能

- **物品档案**：编号、名称、规格、分类、单位、库位、安全库存，支持停用/恢复/删除
- **独立二维码**：每个物品一个二维码，内容就是物品编号（纯 ASCII，扫码枪 / PDA 也能读）
- **扫码出入库**：扫码或手输编号 → 选入库/出库 → 填数量，库存与流水自动更新（服务端行锁保证并发安全）
- **流水追溯**：谁、什么时候、对哪个物品、做了多少，前库存 → 后库存链条完整可查
- **库存预警**：低于安全库存的物品自动挑出来
- **人员与审批**：员工账号由主管添加、管理员审批后才可登录
- **电脑端工具**：粘贴 Excel 批量建档 → 生成编号与二维码标签 → 打印 → 导出 CSV，再粘贴进小程序批量导入

## 三种身份

登录后按账号的身份直接进入不同的后台。

| | 管理员 | 主管 | 员工 |
|---|---|---|---|
| 后台名称 | 管理中心 | 主管台 | 工作台 |
| 底部导航 | 4 项（无扫码） | 5 项 | 5 项（**扫码是中间凸起的大按钮**） |
| 建档 / 改档 / 导入 | ✅ | ✅ | ❌ |
| 扫码出入库 | ✅ | ✅ | ✅ |
| 添加账号 | ✅ 直接生效 | ✅ 提交待审批 | ❌ |
| 审批账号 | ✅ | ❌ | ❌ |
| 删除物品 / 导出记录 | ✅ / ✅ | ❌ / ✅ | ❌ |

底部导航、标题、主题色、首页内容、按钮可见性全部由 `utils/roles.js` 一份配置驱动。

**员工不能自己注册**：主管添加 → 状态 `pending`，此时登录会被拦（`ACCOUNT_PENDING`）；
管理员审批通过 → `active`，才能登录，且首次登录会被要求修改初始密码。

## 本地运行

1. 用微信开发者工具打开本目录（小程序根目录就是仓库根目录）。
2. 安装依赖并构建 npm：
   ```bash
   npm install
   ```
   然后在开发者工具里执行「工具 → 构建 npm」，生成 `miniprogram_npm/`（仓库里已包含一份构建产物，
   升级 SDK 后需要重新构建）。
3. 编译预览。首次登录会提示修改初始密码（仅针对审批通过的新账号）。

云环境配置集中在 `utils/cloud.js` 的 `publicConfig`（endpoint + publishableKey），换环境只改这里。

## 后端

数据落在 WorkBuddy 云服务（PostgreSQL）。关键设计：

- 数据是**团队共享**的，不是按人隔离；`items` 对客户端只开放只读（扫码查物品需要）。
- `stock_records` / `staff` / `staff_sessions` **零表级授权**，所有写入必须经过带令牌的
  `SECURITY DEFINER` 函数 —— 绕过界面直接调接口也拿不到越权数据。
- 库存只能通过 `stock_change(p_token, ...)` 修改（内部 `SELECT ... FOR UPDATE` 行锁 + 写流水），
  客户端不允许直接 update `items.qty`。
- 密码用 `pgcrypto` 的 bcrypt 存储；登录成功后下发 30 天有效的令牌。
- 登录失败时也会跑一次 hash 比较（诱饵），避免按响应时间枚举账号。

## 电脑端工具

直接双击打开 `pc-tools/index.html` 即可（纯前端离线，不依赖后端）。
注意它依赖 `../utils/qr.js`，**不能单独把这个文件拷走**。

流程：粘贴 Excel → 生成编号 + 二维码标签 → 打印 → 导出 CSV / 复制表格 → 小程序「我的 → 批量导入」粘贴。
